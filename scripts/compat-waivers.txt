# Backward-compatibility waivers.
#
# One "<from>-><to> <pointer>" per line, sorted, '#' for comments.
# A waiver is how a KNOWN narrowing stays visible instead of being hidden by
# weakening the gate. Every entry must say what was checked and why it stands.
#
# Convention borrowed from protocolbuffers/protobuf's conformance failure_list
# (BSD-3-Clause): a strict gate is only adoptable if history it cannot change
# can be recorded rather than silently tolerated.
#
# Pre-0.7.1 pairs are not waived individually. Those schemas predate the
# compatibility promise and are not synced with forge-cli (see
# scripts/schema-versions.json); check-compat.py starts at 0.7.1 by default
# (PROMISE_FLOOR) and reports the earlier pairs only with --all-history.

# ---------------------------------------------------------------------------
# 0.7.1 -> 0.7.2  --  REAL BREAK, SHIPPED. Not benign; waived only because it
# is history that cannot be un-shipped.
#
# $defs/notification gained "additionalProperties": false. A contract carrying
# any extra member on a build.execution.notifications[] entry validated under
# 0.7.1 and is rejected by 0.7.2.
#
# Verified with an actual document, plus a negative control that isolates the
# cause (the same document minus the extra member validates under both):
#     build.execution.notifications[0].retryOnFailure
#     0.7.1: VALID    0.7.2: REJECTED (additionalProperties)
#
# docs/releases/0.7.2.md USED TO say "100% backward compatible with 0.7.1" and
# "No breaking changes". Both were false. The note was corrected in #46 and now
# opens by naming the break: "One breaking change, corrected here after the
# fact". The instruction this paragraph used to carry is therefore done, and
# leaving it standing would send the next reader to fix something already fixed.
#
# The waiver itself stays, permanently. 0.7.2 is published and its history
# cannot be rewritten, so the gate has to be told this break is known rather
# than new. What a waiver must never become is a way to stop the gate
# complaining about a break nobody dealt with -- this one was dealt with by
# correcting the release note, not by adding this line.
0.7.1->0.7.2 /$defs/notification

# ---------------------------------------------------------------------------
# 0.7.2 -> 0.7.3  --  FALSE POSITIVE. A widening, not a narrowing.
#
# $defs/identifier: ^[a-z0-9_]...$ -> ^[A-Za-z0-9_]...$ (uppercase admitted).
# Regex containment is undecidable in general, so the gate reports any changed
# pattern as breaking and asks for a decision rather than guessing.
#
# Verified exhaustively: 11,110 strings up to length 4 over the alphabet
# "abz09_.-AZ" were generated; every string the 0.7.2 pattern accepts, the
# 0.7.3 pattern also accepts. Zero counterexamples.
0.7.2->0.7.3 /$defs/identifier

# ---------------------------------------------------------------------------
# 0.7.3 -> 0.7.4  --  INTENTIONAL, and outside what the promise covers.
#
# properties/fluidVersion changed from const "0.7.3" (with a pattern) to enum
# ["0.7.3", "0.7.4"]. The gate reports "enum constraint added" because 0.7.3
# had no enum. Every value 0.7.3 accepted is still accepted. This is the
# version gate doing its job: a document declares the schema version it
# targets, and that member is expected to move with the release. The empirical pass in check-compat.py normalises
# fluidVersion across versions for exactly this reason.
#
# Re-examine if the enum ever DROPS a version that a supported release still
# admits -- that would strand real documents rather than just old version
# strings.
0.7.3->0.7.4 /properties/fluidVersion

# ---------------------------------------------------------------------------
# 0.7.6 -> 0.7.7: DELIBERATE, in a PREVIEW. A widening with one narrow edge.
#
# $defs/airflowOrchestration/properties/dagId and
# $defs/airflowTask/properties/taskId. Through 0.7.6, and in every copy of
# 0.7.7 published here before forge-cli v0.38.0, the pattern was
# ^[a-z0-9_][a-z0-9_.-]*[a-z0-9_]$|^[a-z0-9_]$ with no length limit. Both ids now
# follow the ASCII part of Airflow's own rule: the pattern
# ^[A-Za-z0-9_.-]+(?![\s\S]) with minLength 1 and maxLength 250. That is ASCII
# letters of either case, digits, underscore, dot and dash, at most 250
# characters. The end of the pattern is (?![\s\S]), "nothing follows", not $,
# so that the same id is accepted or refused by every validator: in ECMA-262 a
# $ matches only at the very end, but in Python's re it also matches before a
# final newline, so a pattern ending in $ accepted "abc\n" in one language and
# refused it in the other. The same change made dagId optional
# ($defs/airflowOrchestration no longer requires it), which only widens.
#
# Regex containment is undecidable in general, so the gate reports any changed
# pattern as breaking, and reports minLength and maxLength as tightened because
# 0.7.6 had neither. The decision rests on two facts.
#   - Every string the old pattern accepts uses only characters the new one
#     allows, so the patterns alone narrow nothing under ECMA-262. Checked on
#     66,430 strings: every string of up to 5 characters over the 9 symbols
#     a Z 0 _ . - space, newline and a non-ASCII letter. With ECMA-262 regular
#     expressions 0 strings accepted by 0.7.6 are refused by 0.7.7, and 7,923
#     are newly accepted (upper case, and a leading or trailing dot or dash:
#     Customer_DAG, -daily, daily.). With the published schemas' own
#     validators in Python the one difference is a trailing newline: 282 of
#     those strings, every one ending in a newline ("abc\n"), were accepted by
#     0.7.6 because Python's $ matches before it, and are refused by 0.7.7. No
#     ECMA-262 validator ever accepted them, and an id that ends in a newline
#     is not one Airflow accepts. Nothing else is refused.
#   - What 0.7.6 accepts and 0.7.7 now refuses is, besides that, an id longer
#     than 250 characters: 250 characters of "a" is accepted by both, 251, 252
#     and 1000 only by 0.7.6, and the empty string is refused by both.
#     Airflow's own limit on a DAG id and a task id is 250 characters, so no id
#     Airflow accepts is affected.
#
# Why it stands: 0.7.7 is a preview and a contract reaches it only by declaring
# "0.7.7". The old pattern refused ids Airflow accepts, which made a DAG that
# already existed in Airflow impossible to describe. The 0.7.7 corpus pins both
# sides (tests/0.7.7/orchestration.json), including an id that ends in a
# newline, which the previous pattern accepted under Python.
# docs/schema/changelog.md and docs/releases/0.7.7.md say the pair is not
# purely additive.
#
# MAINTAINER DECISION implied: that a preview may narrow an id's length, to the
# 250 characters Airflow itself allows.
#
# Re-examine when 0.7.7 is promoted: a stable version may not narrow.
0.7.6->0.7.7 /$defs/airflowOrchestration/properties/dagId
0.7.6->0.7.7 /$defs/airflowTask/properties/taskId

# ---------------------------------------------------------------------------
# 0.7.6 -> 0.7.7: DELIBERATE, in a PREVIEW. A widening with a narrow edge.
#
# $defs/column/properties/type, the pattern (second anyOf branch). An enum's
# parameters are now a comma-separated list of levels. A level is a quoted
# string, in single or double quotes, that may hold any character but a
# control character, with its own quote doubled as SQL writes it, or an
# unquoted list of words. Through 0.7.6, and in every copy of 0.7.7 published
# here before forge-cli v0.32.0, the parameters were any run of letters,
# digits, underscores, spaces, commas, quotes and hyphens. Every other type
# keeps that character set.
#
# Regex containment is undecidable in general, so the gate reports any changed
# pattern as breaking and asks for a decision. This one rests on comparing the
# two patterns on 1,195,741 strings: every string of up to 5 characters (6
# after "enum(") over the 9 symbols  a 0 - space , ' " . )  after each of the
# 10 prefixes "enum(", "ENUM (", "varchar(", "decimal(", "timestamp with time
# zone(", "map(", "enumx(", "enum", "string" and the empty prefix. A second
# comparison covers 618,821 strings: every string of up to 4 characters (5
# after "enum(") over the 13 symbols  a ' " , ) -  space, tab, newline, DEL,
# U+0085, a non-ASCII letter and ">"  after each of the 8 prefixes "enum(",
# "ENUM (", "varchar(", "decimal(", "map(", "enum", "string" and the empty
# prefix. In both:
#   - no type other than enum changes its verdict;
#   - what 0.7.6 accepts and 0.7.7 now refuses (21,676 strings in the first
#     run) is an enum with an empty item, a quote that does not open and close
#     a level, or a whitespace control character inside a quoted level:
#         enum(a,,b)   enum(a, )   enum(')   enum('it's')   enum('a'  'b')
#         enum('a<TAB>b')
#   - what 0.7.6 refuses and 0.7.7 now accepts (960 strings in the first run)
#     is an enum with a quoted level that holds a character 0.7.6 refused:
#         enum('Dr.', '>10000', 'O''Brien', 'a, b')   enum("Dr.", "Cir.")
#   - unchanged: enum   enum()   enum(IE, United Kingdom)   varchar(255)
#     decimal(18,4)   varchar('1, 2')
#
# Why it stands: 0.7.7 is a preview and a contract reaches it only by declaring
# "0.7.7". The new grammar is what lets a level hold any character, and the
# spellings it refuses are the ones it cannot read as a list of levels. The
# 0.7.7 corpus pins both sides (tests/0.7.7/contract-schema.json).
# docs/schema/changelog.md and docs/releases/0.7.7.md say the pair is not
# purely additive.
#
# Re-examine when 0.7.7 is promoted: a stable version may not narrow.
0.7.6->0.7.7 /$defs/column/properties/type/anyOf/1

# 0.7.6 -> 0.7.7: DELIBERATE, in a PREVIEW. The others in the pair are
# the column type pattern and the Airflow ids, above.
#
# secretRef (acquisitionSource.connection, acquisitionDeployment.auth and the
# kafka-connect schema_registry.auth) was a string matching
# ^[a-z][a-z0-9_+.-]*://.+ . It is now the shared $defs/secretRef: an anyOf of

#     build.properties.source.connection.secretRef = "vault://secret/data/crm-db"
#     0.7.6: VALID    0.7.7: REJECTED (anyOf)
#     "vault://secret/data/crm-db#password": VALID under 0.7.7
# A secretRef that already carried #field, or used another scheme, stays valid.
#
# Why it stands: 0.7.7 is a preview, a contract reaches it only by declaring
# "0.7.7", and the change comes from the reference implementation's
# "secret references end to end" work. The 0.7.7 corpus (tests/0.7.7/
# acquisition.json) was updated to the new grammar. docs/schema/changelog.md and
# docs/releases/0.7.7.md say the pair is not purely additive.
